# Cascade 1.16.0

Release 1.16.0 turns the multi-day soak plan into a fail-closed authenticated RF=3 qualification campaign. It does not claim that the required 72-hour run has already happened.

## What changed

- The production profile starts three brokers with replication factor three, minimum ISR two, synchronous flushing, separate durable directories, and authenticated peer TLS.
- Every tenant has its own `SASL_SSL` identity, ACL scope, topic, transaction ID, producer, and exact `read_committed` verifier.
- The workload continuously commits transactions, periodically aborts transactions, checks acknowledged offsets and deterministic payloads, and rejects every missing, duplicate, reordered, corrupt, or unexpectedly visible value.
- Elapsed-time schedules force consumer rebalances, active-controller failover and restart, and live CA/leaf/trust rotation even when broker throughput changes.
- A final three-broker restart replays the complete committed ledger from offset zero and compares it with the first verification pass.
- Atomic JSON evidence records the clean Git revision, configured and actual duration, exact counters, heap high-water mark, fault counts, quota decisions, authentication totals, audited tenant count, and restart result.
- The PowerShell wrapper rejects stale evidence directories, dirty release candidates, non-Java-21 runtimes, missing reports, skipped events, authentication failures, quota rejection, and incomplete exact recovery.
- Generated campaign certificates outlive the requested run with a safety margin instead of expiring during a multi-day test.

The [authenticated soak runbook](../authenticated-soak.md) defines the command, evidence, acceptance contract, failure handling, and remaining external boundaries.

## Focused qualification

The forced two-tenant smoke commits, verifies, and recovers every generated record, aborts one transaction per tenant and cycle, performs one consumer rebalance, rotates the complete TLS trust path, removes the active controller, elects a replacement, restarts the removed broker, and restarts the complete cluster. Its assertions derive exact totals from the cycles actually completed, so machine speed cannot turn a successful extra cycle into a false failure. It records hundreds of distributed quota reservations and successful authentications with zero mismatch, quota rejection, or authentication failure.

This short run exists to prove every harness phase and fail-closed assertion. It is not multi-day stability evidence. On 2026-10-24 the complete Scala/Kafka-client regression passed **692/692** tests with zero failures or errors in **206 seconds**. Immutable image qualification remains a separate release gate.

## Container status

The repository builds `miladsade96/cascade:1.16.0` from the pinned Alpine/musl Java 21 runtime. A local build is not Docker Hub publication. The final image must pass packaged runtime, five-language clients, the five-version Java matrix, the 1.15.0-to-1.16.0 adjacent-image campaign, SBOM/provenance generation, and the authenticated zero-finding security gate before publication.

## Boundaries

This release implements the complete in-process authenticated soak schedule. It does not replace the untouched 72-hour evidence run, independent broker hosts, dedicated-host RF=3/TLS capacity measurements, arbitrary external packet impairment, physical power/device loss, encrypted off-host snapshot restore drills, or future adjacent published-image gates. I do not describe Cascade as a universal production replacement for Apache Kafka while those gates remain open.
