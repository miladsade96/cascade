# Cascade 1.10.0

Release 1.10.0 completes record-level compaction rewriting for every Kafka magic-v2 compression codec Cascade accepts.

## What changed

- Closed-segment compaction now decodes and rewrites Snappy, LZ4, and Zstd batches in addition to uncompressed and Gzip batches.
- Rewritten batches preserve their original compression type, base and last offsets, timestamp envelope, record bytes, producer identity, epoch, and sequence span.
- Compaction recalculates the Kafka batch length, retained record count, compressed payload, and CRC32C before the atomic `.cleaned` replacement.
- Decompression is bounded at 128 MiB per batch. Malformed, unknown, control, and transactional batches retain the existing conservative behavior.
- Runtime codec dependencies use Snappy Java 1.1.10.12, LZ4 Java 1.12.0, and Zstd JNI 1.5.7-23.
- The minimal container stores the three Linux/amd64 native libraries in its read-only application tree. Codec loading no longer depends on extracting executable files into `/tmp`, so the documented read-only root and `noexec` temporary filesystem remain enforced.

## Verification

On 2026-10-20 I ran the focused storage and real-client gate after updating the runtime dependencies. All **30/30** tests passed in 39 seconds. The gate checks decode/rewrite/CRC behavior for Gzip, Snappy, LZ4, and Zstd; closed-segment and tombstone behavior; and Kafka Java 4.3.1 consumption of rewritten Snappy, LZ4, and Zstd batches with exact keys, values, and offsets.

I then ran the complete suite on Eclipse Adoptium Java 21.0.11. All **614/614** unit, integration, Kafka-client, fault, security, storage, deployment, and end-to-end tests passed in 192 seconds with no failures or errors.

## Version and container status

`VERSION`, `deploy/VERSION`, Compose, Kubernetes, the Dockerfile default, compatibility package, scripts, and current documentation use 1.10.0. The local image tag is `miladsade96/cascade:1.10.0`.

Building a local tag is not a Docker Hub publication or a security approval. I require the exact immutable image to pass runtime checks and the authenticated zero-finding security gate before publishing it, and I do not move `latest` implicitly.

## Remaining boundary

This release closes the local compression-codec compaction gap. It does not complete replicated cleanup coordination, a 72-hour authenticated multi-tenant soak, dedicated-host RF=3/TLS capacity, coordinated cross-host snapshots, published-image rolling qualification, or physical power/device-loss testing. I still do not describe Cascade as a universal production replacement for Apache Kafka.
