# Cascade 1.7.0

Release 1.7.0 replaces permanently divided cluster quota shares with exact, dynamically reclaimable cluster-wide capacity.

## What changed

- The active metadata controller serializes per-principal request, response, Produce, and Fetch reservations against one cluster bucket.
- Idle brokers reserve nothing, so active brokers can use otherwise stranded capacity without increasing the configured aggregate rate or burst.
- A new controller term starts with zero quota tokens and earns capacity at the configured rate, preventing burst reuse after failover.
- Level-2 activation requires every voter to advertise and commit support. Mixed clusters retain the conservative level-1 equal-share behavior.
- Broker setting mismatches and ambiguous coordinator failures fail closed. Peer quota RPCs are authenticated and excluded from recursive client accounting.
- Acknowledged egress waits the full required delay; it is never released early merely because the ingress rejection threshold was reached.
- Prometheus exposes controller term, reservations, decisions, forwarding, epoch resets, configuration mismatches, and coordination failures without principal labels.

## Compatibility and storage

The public Kafka API range and metadata format remain unchanged. The internal authenticated peer API gains quota reservation key `-130`, and the `distributed-quotas` negotiated feature advances from level 1 to level 2. No data or coordinator storage migration is required.

## Qualification boundary

Unit and real three-broker tests cover codec bounds, per-principal/class isolation, concurrent serialization, idle-capacity reclamation, feature activation, configuration mismatch, authenticated forwarding, and controller failover. The complete suite and exact image gates are recorded after the release candidate is built. This release does not claim completion of the 72-hour authenticated soak, dedicated-host RF=3 quota capacity, physical device-loss work, or Docker Hub publication.
