# Cascade 1.3.1

Status: security patch in qualification; not yet published. Target: `miladsade96/cascade:1.3.1`, Linux/amd64 only. I will record the tested image identity and publication evidence before marking this release published.

## Security changes

The post-publication scan of 1.3.0 found 21 vulnerabilities: one critical, three high, three medium, ten low, and four unspecified. Seven were attributed to `libssl3` and fourteen to `libc6`. The original scan failure was a release-process gap, not a clean result. The [1.3.0 notes](1.3.0.md) preserve the historical qualification and subsequent finding.

I replace `base-debian12` with `base-nossl-debian13`, pinned to `sha256:5cab74e7f8a5e7c5f1c8a9e6268b1f352f053c36c656f493308340bcecbc636c`. This removes the OpenSSL libraries rather than hiding their package metadata, and updates the glibc base. Cascade uses Java's TLS implementation; I qualify TLS/SASL and peer security with the packaged JVM and broker jars before publication. The JDK build input remains pinned to Temurin 21.0.12+8. No broker protocol, storage format, or metadata feature level changes in this patch.

The candidate base scanned clean. That result alone does not qualify the final application image. I require the [release security gate](../container-security.md) to scan the complete attached inventory, including the JDK and Scala jars. The gate rejects every severity, scanner errors, incomplete inventory, wrong image identities, and stale output-directory reuse. No CVE exceptions, severity filters, or base-package exclusions are configured.

The release workflow builds once, tests the actual image, scans it, and passes the exact image archive to publication. Publication scans again and pushes that image without rebuilding. Only Linux/amd64 and the explicit version tag are published; ARM64 needs its own runtime qualification before re-enabling it. `1.3.0`, `latest`, and Git branches are not pushed or changed by this release operation.

Pending: full Scala suite, security-gate regression tests, packaged-image TLS/SASL and peer-security tests, five external client languages, single-node restart, three-broker replication/restart, final image vulnerability scan, and immutable Docker Hub digest verification.

A clean scan is point-in-time inventory evidence, not proof of zero undiscovered vulnerabilities or universal exploitability coverage.
