# Cascade 1.6.0

Release 1.6.0 completes the current delivery-semantics milestone without claiming Kafka transaction protocol V2 or overall production readiness.

## Delivery surface

- Producer initialization supports v0-v5 and idempotent expected producer ID/epoch retries.
- Transaction partition admission supports v0-v5, flexible framing, batched transactions, and verify-only checks.
- Transaction group enrollment, completion, and offset commit support v0-v4 with flexible v3-v4 layouts.
- Transactional offset commits validate classic generations and modern consumer member epochs before staging offsets.
- Kafka Admin can describe retained producer sequence state, describe active transactions, and list transactions with state, producer, duration, and regular-expression filters.
- Acknowledged immutable views keep administration and `read_committed` decisions isolated from failed or in-progress coordinator publication.

I intentionally cap `EndTxn` and `TxnOffsetCommit` at v4. Their v5 schemas require Kafka transaction protocol V2 behavior that is not implemented in this release. `InitProducerId` v6 is also excluded because it is Kafka's unstable two-phase-commit extension.

## Source qualification

On 2026-09-14, Eclipse Adoptium Java 21.0.11 passed the complete **564/564** Scala and Kafka-Java unit, integration, end-to-end, fault, security, and qualification suite in **179 seconds**, with no failures or skips.

The dedicated development-host transaction campaign used 256 independent transactional IDs at concurrency 16. It verified exactly 256 committed values, 512 values under `read_uncommitted`, and the same 256 committed values after broker restart, with zero missing or unexpected values. The run completed in 11.183 seconds. Commands, coverage, and limitations are in the [delivery semantics qualification](../performance/2026-09-14-delivery-semantics.md).

## Remaining production gates

This release is not yet a production-grade Kafka replacement. Kafka transaction protocol V2, a broader producer/client version matrix, the authenticated 72-hour multi-tenant soak, dedicated-host RF=3 transaction and membership capacity, arbitrary packet impairment, coordinated multi-host restore drills, and physical power/device-loss qualification remain open.
